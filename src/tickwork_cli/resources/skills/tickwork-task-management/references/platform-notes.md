# Native scheduling and diagnostics

All calendar times use this device's local time zone, including native DST rules. Interval is a native start-to-start rule in whole minutes (60..86400 seconds), not a wall-clock promise. Tickwork never wakes a sleeping host, retries failures or implements catch-up. Native clock changes, sleep and session differences still apply.

- Linux: systemd user service/timer, `Persistent=false`; calendar triggers while inactive are not replayed. The user manager must run. Check `doctor` lingering information. Tickwork never enables lingering; logout can stop scheduling. Inspect `journalctl --user -u <unit>.service` and `systemctl --user show <unit>.timer`.
- macOS: launchd GUI user agents require a logged-in GUI session. StartInterval skips intervals during sleep; StartCalendarInterval may coalesce missed calendar events into one on wake. This is launchd behavior, not a Tickwork replay queue. Inspect `launchctl print gui/<uid>/<label>` and unified launchd logs. A headless session without GUI domain is unavailable.
- Windows: Task Scheduler, current user InteractiveToken with LeastPrivilege, requires that user logged in. StartWhenAvailable=false, MultipleInstancesPolicy=IgnoreNew. No stored passwords, SYSTEM or elevation. Inspect LastTaskResult and Microsoft-Windows-TaskScheduler/Operational. Noninteractive credentials/environment differ from terminal shells.

Native entries are scoped by a hash of the absolute Tickwork home path and task id; ownership markers must match before mutation. Changing the home path does not adopt old native entries. A missing Python environment or executable may fail before SQLite can record a run. Reinstalling elsewhere requires explicitly redeploying tasks with update/resume.

Execution uses argv directly, never an implicit shell. For shell syntax supply an explicit shell and its arguments. Use absolute executable and cwd. Tasks inherit the native scheduler environment, not your interactive shell configuration; keep secrets out of argv and task files. Use a wrapper to establish needed environment or credentials. Timeout terminates the child process tree. Same-task overlap is skipped with an OS file lock independently of SQLite; busy mutation rejects instead of killing a run.

Logs are streamed into SQLite in chunks, UTF-8 with replacement of invalid bytes, with a combined 10 MiB stdout/stderr limit per run. Output continues to drain after the limit; truncated=true exposes truncation. Queries paginate by sequence cursor. On each new run completed history older than 30 days or beyond the latest 99 completed records is pruned; current run adds a record. Active/interrupted histories are not silently removed. Abruptly killed runners can leave running records; check PID/native diagnostics before assuming activity. SQLite/WAL files can be deleted only when no runs/queries are active; historical data cannot be recovered.

Sources: [systemd.timer](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html), [Apple scheduling](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html), [Windows task XML](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema).
